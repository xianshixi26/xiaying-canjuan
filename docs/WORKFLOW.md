# 开发工作流（WORKFLOW）

> 目的：让项目**可追溯、可回滚**，每一步都由设计者验收把关。
> 生效日期：2026-11-07（决策 D-010）

---

## 1. 工作模式：一问一答 + 逐步验收

固定循环：

1. **问**：我提出下一个步骤（做什么 / 怎么做 / 产出物 / 验收标准）。
2. **答**：设计者拍板（同意 / 修改方向后再做）。
3. **做**：我实现这一个小步骤。
4. **验收**：设计者检查成果——
   - 回复 **「通过」** → 进入下一步；
   - 回复 **「不通过：原因」** → 我返工，直至通过。

步骤粒度：一次只做一个可独立验收的小步骤（原则：30 分钟内可完成、可演示）。禁止一次性堆积大量未验收内容。

## 2. 决策与需求管理（回滚基础）

- 所有方案决策记录于 `docs/DECISIONS.md`，编号 **D-XXX**，按序递增。
- 决策状态：🟢 生效 / 🔴 推翻（推翻时注明被哪条决策取代，**原记录保留不删除**）。
- 需求变更流程：**提出变更 → 记录决策 → 更新 PRD（版本号 +1）→ 再动代码**。
- 红线：禁止未记录的需求变更；禁止未验收的代码入库。

## 3. 版本控制（Git）与回滚

- 仓库位置：`wuxia-game/` 根目录。
- 提交规范：`[Step <阶段.步骤>] 简述`，例如 `[Step 1.2] 玩家移动与碰撞`。
- 文档修改与代码修改**分开提交**，便于单独回滚。
- 里程碑：每阶段验收通过后打 tag `phase-N-done`；文档定稿打 tag `docs-vN`。

**回滚流程（三选一）**：

1. **小步返工**（首选）：新提交修正，`git revert` 引入问题的提交，保留完整历史。
2. **整步重来**：`git reset --hard <上一个验收通过的提交>`（仅限未推送的本地提交）。
3. **文档回滚**：PRD/决策日志独立提交，可单独 revert。

回滚后必须在 `docs/DECISIONS.md` 追加一条回滚决策（回滚了哪一步、原因、替代方案）。

## 4. 状态看板

`README.md` 维护「当前状态」区：

- 当前阶段 / 当前步骤
- 待验收项
- 阻塞问题

每完成一步更新；验收通过后立即更新为下一步。

## 5. 沟通约定

- 全程中文。
- **一次一问**：我每次只抛出一个决策点或一个验收请求，不一次性倾倒大量问题。
- 验收回复建议格式：`通过` 或 `不通过：<原因/期望效果>`。
- 设计者可随时提出需求变更，按 §2 流程执行。
- 制作流程固定为：**问 → 答 → 做 → 验收**，四步一循环。

## 6. 步骤模板（我每次使用）

```
【步骤 Phase X.Y】
目标：一句话
产出物：文件/场景/文档列表
验收标准：
  □ 清单项 1
  □ 清单项 2
影响范围：新增/修改的文件
```

## 7. 阶段规划

见 `PRD.md §6`。阶段顺序：初始化 → 战斗原型 → 组合招式 → 探索养成 → 昼夜剧情 → 轻功 → 联机。
